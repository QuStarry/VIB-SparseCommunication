本仓库未采用传统构建系统（无 Makefile、Dockerfile、CI 配置、setup.py/pyproject.toml 等），而是以 Python 脚本 + requirements.txt 的极简方式组织依赖与运行入口。核心约定如下：

1. 依赖管理
- 使用根目录 `requirements.txt` 声明全部运行时与测试依赖，版本约束宽松（如 `>=2.2.0`），未使用虚拟环境或锁定文件（lock）。
- 安装方式：`pip install -r requirements.txt`。

2. 包结构
- 源码位于 `src/`，通过 `sys.path.insert(0, 'src')` 在顶层脚本中直接导入模块；未发布为可安装包，无 `__init__.py` 外的打包元数据。

3. 运行与验证入口
- `validate_milestone1.py`：验证 VIB Router 数学公式（高冗余 vs 高价值消息的效用排序）。
- `validate_milestone2.py`：验证 LangGraph 工作流集成，断言步骤数、候选数、通过率与压缩率。
- `run_summary.py`：汇总 Milestone 1 & 2 结果并打印统计摘要。
- 所有脚本均以 `if __name__ == "__main__": sys.exit(...)` 形式提供 CLI 入口，成功返回 0，失败返回非零。

4. 测试
- 使用 pytest（`tests/test_vib_router.py`），但未见 `pytest.ini` / `tox.ini` / `noxfile.py` 等配置文件，默认按 pytest 约定发现测试。

5. 缺失项（当前不存在）
- 无 Dockerfile / docker-compose / CI（GitHub Actions 等）/ 版本发布流程 / 交叉编译 / 预提交钩子 / lint 配置。

开发者约定
- 新增功能后，优先编写对应的 `validate_milestone*.py` 风格脚本作为“可执行文档”，用断言表达期望行为。
- 如需引入新依赖，追加到 `requirements.txt` 并保持 `>=` 语义，避免硬编码版本号。
- 保持 `src/` 下模块扁平化，顶层脚本通过 `sys.path.insert(0, 'src')` 直引，暂不引入包分发机制。
