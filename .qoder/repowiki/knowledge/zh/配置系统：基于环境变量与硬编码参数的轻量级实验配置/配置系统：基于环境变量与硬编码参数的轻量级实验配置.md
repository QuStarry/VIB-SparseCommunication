该仓库未实现统一的配置管理系统，而是采用**分散的环境变量 + 脚本内硬编码参数**的轻量级方式管理运行时配置。具体模式如下：

1. **凭据与环境变量**：所有外部 API 密钥通过 `os.environ.get("DEEPSEEK_API_KEY")` 读取，由 `src/llm_client.py` 在构造时校验缺失并抛出 `ValueError`；`experiments/run_ablation.py`、`experiments/run_e2e.py` 等入口脚本也各自独立检查该变量。
2. **模型与客户端参数**：`DeepSeekClient.__init__` 将 `base_url`、`model`、`temperature`、`max_tokens` 作为构造函数默认值（如 `"deepseek-chat"`、`0.7`、`1024`），调用方直接覆盖，无集中配置文件。
3. **算法超参**：VIB 稀疏通信路由器的关键超参 `beta_0`、`lambda_decay`、`temp_tau`、`gamma` 全部以 Python 常量或函数参数形式硬编码在 `experiments/run_ablation.py` 和 `run_e2e.py` 中，并通过命令行 `--quick` 切换参数网格大小。
4. **任务定义**：实验任务列表 `EXPERIMENT_TASKS` / `ABLATION_TASK` 直接写在脚本顶部，未外置到 YAML/JSON 等文件。
5. **依赖声明**：仅使用 `requirements.txt` 声明 Python 包版本，无 `pyproject.toml`、`setup.cfg` 或 Docker 配置。
6. **结果输出**：实验结果以 JSON 写入 `experiments/results/` 目录，文件名带时间戳，无统一配置来指定输出路径。

**开发者应遵循的规则**：
- 新增外部服务凭据时，统一通过 `os.environ.get(<VAR>)` 读取并在构造处校验非空；
- 调整模型/路由超参应在对应实验脚本顶部常量区修改，避免散落各处；
- 如需持久化配置，建议引入 `pydantic-settings` 或 `omegaconf` 统一管理，当前仓库尚未采用此类框架。
