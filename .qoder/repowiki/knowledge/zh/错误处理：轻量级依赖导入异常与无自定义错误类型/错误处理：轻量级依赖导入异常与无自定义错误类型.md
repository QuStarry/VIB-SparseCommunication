本仓库未建立统一的错误处理体系，整体采用 Python 标准库的 try/except + raise 模式，且仅覆盖可选依赖缺失这一种场景；业务逻辑层（VIB 路由、LangGraph 工作流）中未发现任何自定义异常类、错误码或结构化错误对象。

1. 使用的系统/方法
- 仅在两个位置使用 try/except ImportError 捕获可选依赖 sentence-transformers 和内部模块 vib_router 的导入失败，并主动 raise ImportError(...) 给出安装提示。
- 其余代码路径全部不显式捕获异常，依赖调用方自行处理。
- 未使用 logging.error / logger.error 等日志记录手段，也未定义任何 Exception 子类作为领域错误类型。

2. 关键文件与位置
- src/vib_router.py：第 72–78 行，在 encoder 属性懒加载时捕获 ImportError 并抛出带安装说明的 ImportError。
- src/workflow.py：第 13–16 行，对 .vib_router 与裸 vib_router 做双路导入回退，若均失败则直接让 ImportError 向上传播。

3. 架构与约定
- 错误传播策略：向上冒泡至调用者（例如 run_summary.py、validate_milestone*.py），由顶层脚本决定如何呈现。
- 状态流转层（AgentState TypedDict、VIBMultiAgentWorkflow）不包含任何 try/except 包裹，假设上游节点函数总是返回合法数据。
- 数值计算部分（余弦相似度、log-sum-exp）通过加 1e-9 做数值稳定，而非抛出数值异常。

4. 开发者应遵循的规则
- 如需新增业务错误（如参数非法、模型加载失败、嵌入维度不一致等），建议统一继承自一个自定义基类（例如 class VIBSparseCommError(Exception): pass），并在各模块中 raise 具体子类，以便上层集中捕获与格式化。
- 对于外部依赖缺失，可沿用现有 ImportError 风格，但建议封装为统一的“环境检查”入口，避免散落多处。
- 当前 LangGraph 节点函数应避免吞掉异常，保持错误向工作流外冒泡，便于测试与监控。
