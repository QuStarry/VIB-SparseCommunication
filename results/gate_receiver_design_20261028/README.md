# 共同候选门控离线设计

本设计没有调用LLM，也没有读取隐藏测试评分或历史通过标签。固定从前两轮72题之外抽32题，seed20261101，不筛选“VIB恰好删消息”的题。

| 项目 | 真实结果 |
|---|---:|
| 固定任务数 | 32 |
| Full共同候选 | 192条 |
| VIB接收 | 129条 |
| 随机消息数匹配接收 | 129条 |
| 余弦消息数匹配接收 | 129条 |
| VIB改变历史的任务 | 28/32 |
| 新API请求 | 0 |

VIB删去63/192条，即32.8125%。随机与余弦逐题、逐轮匹配VIB接收条数，不只是合计129条相同；三种筛选的消息长度不等，因此不是等Token或等实际费用预算。

## 真实编码证据

本地`all-MiniLM-L6-v2`，缓存snapshot `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`，真实384维，CPU/eval，float32/L2归一化。模型与tokenizer文件hash、库版本、实际向量均记录；无网络下载fallback，不用模拟嵌入冒充真实模型。

实际encoder `max_seq_length=256`，长消息被截断。因此utility只基于截断编码，不能称为完整代码语义互信息；路由仍是信息瓶颈启发式，不是训练得到的变分下界。

每题编码公开目标、六个消息正文、六个带角色前缀历史，共13个向量。VIB候选用正文、已批准历史保留角色前缀，与主流程一致；同轮逐条增量历史，而不是旧接收回放的同轮冻结历史。所有六条候选仍来自既有Full，不重新生成下一轮反馈。

## 对照规则

VIB沿用主路由配置与代码差异、纠错关键词、代码角色beta和公开复杂度启发式，不额外添加摘要或最小角色数。随机按task-salted seed在每轮三条消息里不放回抽k条；余弦贪心挑与已选历史最大相似度最小的k条，k来自该题该轮VIB数量。最终保留原消息时间顺序。

这是数量条件匹配对照，随机与余弦不是核心router的Bernoulli/threshold模式，也不是独立先验恒定k。不会把对照收益全部归因于单个utility公式。
